# 月有余 Android 2.0.0

一个中文、本地优先的预算与饮食体重记录应用。包名 `cn.dot.budget`，版本码8，最低Android8/API26，面向Android16/API36。无Google服务依赖。原有Android版本可同签名覆盖升级；升级前建议导出备份。Harmony原生工程是另一个独立项目，本仓库只包含Android版。

## v2.0：四个清楚的饮食页面
十轮内部功能迭代后，只发布一个最终版本。完整逐轮变化、快照哈希及验收记录见docs/ITERATIONS-V2.md。

- 今日：所选日期的图形食物额度、摄入/目标/运动指标，拍照与手动记录快捷入口、常用食物卡片。
- 饮食：所选日期的记录时间线、完整常用食物管理，以及主动标记当天已全部记录。
- 趋势：按实际日期间隔绘制的体重曲线，最多展示最近14条，完整历史仍可编辑，文字说明提供同样数值。
- 计划：本人填写的本地资料、当前估算方式和运动政策，不预填身体资料。

食物、运动、体重和计划采用独立全屏录入流程。营养标签换算在食物录入页默认展开。计算细节按需展开，预算/剩余/预计差额的含义及原有保护规则不变。图表不虚构餐次、时间或未保存数据；没有目标时不会画出假的剩余额度。

## 两种模式
- 预算：月预算8600元（房租2500、交通1000、日常餐饮1500、品质餐饮1600、娱乐电子2000）；日常餐饮默认日限额50元。支持收入、消费、退款、转账、信用卡还款、分类预算、编辑删除、80%/超支提醒。房租仅预算，不自动计入支出；转账还款不重复计支，退款抵减对应分类。
- 饮食与体重：饮食记录、可编辑热量范围/份量、营养标签计算、体重记录与按日期排序的变化。体重只在本机使用，不送入AI请求。支持可选的本地全天热量规划；估算不是实时消耗测量或医疗建议。

点击顶部模式切换。饮食、体重和账目均支持日期、编辑、确认删除；这些数据包含在主动导出的JSON备份中，请妥善保管。

## 外观与选择界面
记账默认雾蓝，饮食默认薄荷青，设置中可分别选择预设颜色或输入十六进制色值。颜色随本地备份保存。选择项使用统一的可键盘操作底部列表，支持取消、返回和焦点恢复。营养标签换算默认展开。

## 全天热量规划（本地）
身体资料默认空白，由本人填写。可用低活动起始估算或手动全天维持热量；初始缺口建议为300 kcal与基线15%的较小值，可自行调整0–500 kcal。预算护栏可能降低采用的缺口，不限制记录实际摄入。

运动记录支持日期、编辑和确认删除。默认只作信息展示，不增加消耗或饮食额度。只有明确确认基线不含这项运动时才增加活动热量，避免重复计算；可选择0或50%作为额外饮食额度，默认0。

界面分别显示摄入、基线、运动、饮食目标、剩余额度和全天预计缺口。未结束当天时预计会吃完目标额度，不将暂未进食当作已实现缺口；主动标记完成后显示按全天记录估算的差额。未满18岁、孕期/哺乳期、体重过低等不提供自动减重目标。资料和运动仅留本机，不发送给AI。完整方法与证据见docs/ENERGY-METHOD.md。

## 常用食物（本地）
可从已记录的饮食保存常用食物，包括名称、默认重量和热量范围。下次选择常用食物后先填入新记录，只有点击保存才新增饮食，不会因点选自动计入摄入量。

修改份量时按原常用份量比例计算热量；可手动修改热量。常用食物支持编辑与确认删除，同名冲突需明确处理。修改或删除常用食物不会更改已经保存的历史饮食。数据只在本机，随主动导出的JSON备份保存，不调用AI或上传。

## 食物照片与营养标签
1. 在设置配置自己的DeepSeek API Key，或首次识别时填写。密钥只在手机原生密码框输入，默认临时使用；主动勾选后用Android Keystore AES-GCM加密保存，可随时清除。备份不含密钥。
2. 在饮食模式调用系统相机拍照，或选择一张已有食物照片。系统相机仅获得单个临时文件授权，无相册全量读取权限，本应用不申请直接摄像头权限。取消不会保存饮食记录。
3. 显示照片与发送/费用提示，确认才向DeepSeek发送。食物照片重编码为JPEG以移除EXIF元数据；只发这一张图与固定提示，不发体重、历史饮食、账目或联系人。
4. AI估算名称、份量和热量区间，必须核对并可修改后保存。照片无法可靠知道实际重量、油量和配方，不能当作精确测量。没有可识别食物、非法范围或缺字段不会自动入库。
5. 有包装营养表时可手动填写kcal或kJ、每100g或每份基准和实际食用克数。1 kcal=4.184 kJ；换算结果可核对再记录，不需要联网。

## 银行账单截图
选择截图→确认发送→逐笔核对→勾选导入。支持保守重复提醒，转账/还款不计收入消费，退款抵减支出。本地账单年份默认2026，可修改并保存；没有年份的月日自动补全。明确年份和手动完整日期保留。日期不可能/不存在或完全无月日时仍需修正，不会猜测。

银行截图发送前建议遮盖姓名、卡号等无关信息。不会自动抓取银行、微信、支付宝数据；仅处理用户选择的图片。人民币以整数分存储；外币无明确人民币金额时需人工填写。

## GitHub更新
固定公开仓库 `wkricardo/yueyouyu-android`。启动时自动检查正式最新版，也可在设置点击检查。发现新版本先提示，用户点击才下载；下载后检查SHA256、包名、递增版本码、发布版本和原签名证书，再由用户确认打开Android安装界面。未知来源权限只能由用户在系统设置自行决定，应用不会静默安装或替用户修改设置。

只接受固定GitHub发布路径和受限GitHub资源CDN，不使用GitHub Token，不把账目/体重发送到GitHub。无网络/限流/没有发布时可继续离线使用。自动检查会向GitHub发起常规版本查询。1.1.x需先手动安装本版本，之后才具备此检查能力。

发布者须上传同一签名的新版本，release tag例如`v2.0.0`，资产为`yueyouyu-android.apk`与`SHA256SUMS`；详情见UPDATE-SECURITY.md。源码不包含签名私钥、API密钥或发布凭据。不要把签名密钥提交到Git。

## 数据、安全和费用
- 手动记账、营养换算、体重记录完全离线；图片AI识别与GitHub更新检查才联网。
- DeepSeek官方端点 https://api.deepseek.com/chat/completions ，模型`deepseek-flash`。每次截图/照片发送前确认隐私与费用，按自己的DeepSeek账户计费。失败/取消也可能已产生费用，无自动重试。
- API只收当前所选图片与提示；应用不会发送体重/旧账目。上传后处理遵循DeepSeek政策，已发送内容无法撤回。
- 数据在应用专属WebView存储，无账号同步、广告或统计追踪。v1/v2/v3/v4数据迁移到schema5；首次迁移写入前保留原本地账本快照。旧版备份可导入；缺少饮食/体重/常用食物的旧备份会提示相应列表为空，导入替换当前全部数据。
- JSON备份明文包含账目、饮食、体重、常用食物、身体资料和运动记录，请存放到可信位置。卸载、清除数据或设备故障可能丢失记录。密钥不进入备份或日志。
- 系统预算通知需主动授权，未授权仍显示应用内警告；通知可能显示在锁屏。

## 构建
安装官方JDK21、Android SDK Platform36、Build-Tools36.0.0以及zip，并按官方要求接受SDK许可。
设置`JAVA_HOME`、`ANDROID_HOME`、`SIGNING_KEYSTORE`、`SIGNING_ALIAS`（默认budget）、`SIGNING_PASSWORD`后执行`./build.sh`。签名凭据只在自己的环境提供，不进入源码。

开发者自行更换签名时，需同时更新GitHubUpdateTransport.CERT中的公开证书SHA256；原签名应用不会接受不同签名的覆盖安装。发布新版本须同时递增Manifest版本码和版本名，保持release tag一致。这里没有自动上传签名秘密的GitHub Actions工作流。

## 测试和已知限制
`npm install`后`npm test`执行模型与真实app.js的jsdom测试。Java测试脚本`tests/run-native-tests.sh`执行模拟传输、更新器和私有文件策略验证。JDK需配置JAVA_HOME。
测试不连接真实DeepSeek服务，无用户照片或真实密钥。jsdom是DOM模拟，不等于Android WebView/视觉实测。当前构建环境未连接Android真机或模拟器，系统相机、Keystore、通知、安装器及实际升级仍需设备端验证。编译与签名通过不等于Mate70所有功能已实测。见docs/TEST-REPORT.md。
